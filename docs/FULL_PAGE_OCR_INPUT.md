# 整屏 OCR 输入衔接（独立实验）

2026-09-25：全宽分段与原屏坐标映射通过本机和目标华为计算验证。实现仅在 modelprobe 测试源集；正式放大镜、采集实验及旧 OCR 参考均未改动。

## 已解决的问题

目标华为为 1176×2400，整屏超过既有源图／检测输入 1,048,576 像素预算。新规划器沿用旧 DetectorPacking，将整页拆成全宽水平条带；输入没有取景框参数，不因选区丢失其他当前可见上下文。

- 支持宽32～2048、高32～4096，整帧至多4,194,304像素；不支持的尺寸明确拒绝，不能当作通用横屏方案。
- 每条带含互不重叠的核心行，上下各最多64原屏像素重叠，合计至多16段。每一原屏行恰有一个核心归属，完整宽度都被读取范围覆盖。
- 每段源图和旧规划器生成的检测输入分别不超过1,048,576像素；不放宽旧预算、改写冻结参考或改变缩放舍入。
- 映射按实际检测宽高分别还原x/y，再加原屏偏移，不假设两个轴缩放一致。
- 华为1176×2400生成4段，模拟器尺寸1080×2400生成3段。后者仅尺寸计算，本轮没有新模拟器设备运行。

核心行归属只是几何信息，**不能直接用作文字去重或删除跨缝片段的规则**。长行、旋转文本、跨缝文字的合并和质量需后续真实模型验证。

## 验证

新增测试先有7项预期行为失败，实现后通过；补充旧自适应阈值／32像素舍入边界成为8项。最终124项modelprobe JVM回归全部通过，主APK／测试APK构建通过，Lint 0错误、6项既有警告。

目标华为LIO-AN00/API31安装后的主包和测试包哈希与本机构建一致；8项同源坐标／预算测试全部通过（0.183秒）。只使用固定尺寸，没有屏幕共享、采集或OCR推理。证据：[summary.json](evidence/full-page-strips/2026-09-25/summary.json)。

复验使用已有JDK17／Android SDK／Gradle缓存：

```sh
./gradlew --offline :modelprobe:testDebugUnitTest :modelprobe:assembleDebug :modelprobe:assembleDebugAndroidTest :modelprobe:lintDebug
adb -s 2KE0220109017133 shell am instrument -w -r -e class com.kandong.modelprobe.FullPageStripPlannerTest com.kandong.modelprobe.test/androidx.test.runner.AndroidJUnitRunner
```

设备测试需先核对目标身份和安装指纹；系统安装由用户确认。

## 后续验收

1. 单个固定版本帧的有界RGBA→BGR分段交接，处理行填充／像素步长、关闭、取消、过期和错误路径。纯字节验证与真实Image适配分别记录，不凭时间或非黑像素制造隐私证明。
2. 顺序复用实际检测／识别会话，回映整屏坐标，保留跨缝来源并验证重复／残缺文字合并。
3. 分别验证单语英语、法语、简体中文、繁体中文整屏文字和位置；结合页面上下文后，再映射选区结果到镜面。
4. 真实来源／隐私过滤、主动翻译和页面版本失效独立验收；本实验不赋予正式放大镜OCR或联网授权。
