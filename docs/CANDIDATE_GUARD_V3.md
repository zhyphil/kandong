# 候选 v3：标点与字母冲突防护

2026-09-24，本项独立实验验收完成；三语识别质量仍未通过，正式放大镜没有变化。仅使用项目合成输入与专用 API37/16KiB 模拟器，未操作妈妈的手机。

## 问题与修正

上一轮新语料出现一个被单独检测的句号框：中文模型输出“。”，Latin 模型输出“o”，v2 选择了字母。该页原先已有分行差异，只看“完全正确的页数”会漏掉这一新增字符错误。失败原文与检查过程见[双字体质量检查](CANDIDATE_HOLDOUT_V2.md)。

规则在 97dc3ef 先固定，再测试和实现：保留非空原文逐字一致及汉字分支；不一致且选择 Latin 时，两候选都须含 Latin 字母。纯数字、标点或空串与字母冲突时返回 REVIEW（待核对），保留两份原文与框位置，不猜测哪一个正确，不依据图片名称或预期答案修正文字。两模型一致仍不等于正确。

当前 `pageText` 遇到任何 REVIEW 会返回空值，块记录仍完整保留。这是实验阶段的保守行为，尚未完成下游部分结果展示；不能将被拦下的句号计为正确识别。

## 复现入口

使用已建立的 KanDong 专用模拟器及本次对应的主/测试 APK，环境见[模拟器说明](OCR_EMULATOR.md)：

```sh
python3 -B scripts/run-candidate-emulator.py --targeted --output /private/tmp/kandong-v3-new-run
python3 -B scripts/replay-candidate-guard-v3.py --output /private/tmp/kandong-v3-new-replay
```

输出目录必须不存在。入口限定专用 AVD、API37、16KiB 和已安装 APK 指纹，拒绝手机与其他模拟器；`--targeted` 为本轮的两组定向测试，省略它可跑完整 14 项。持久入口在实际执行脚本基础上调整仓库路径并增加该参数，原执行脚本按原文归档。
