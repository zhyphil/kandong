# 金额原文保护与有限日期转换（2026-09-24）

本轮完成一个独立的宿主实验：金额及币种的原始写法不交给翻译服务改写；可完整解析的日期有效性标签在本地生成中文。原有放大镜、Android 模块和真机版本没有变化。

新增四张单语合成页共 16 条目标：8 条金额候选通过本次开发语义复核、4 条日期正确本地表达、4 条歧义/例外/非法日期保留完整原文。拒绝转换不计入翻译成功。新旧合计每轮 72 条，两轮状态全部一致，70 对显示文本逐字一致；金额“2人总计/2人共计”与一条复用译文为等价措辞变化。

本轮 18 个金额目标 × 2 轮 = **36 次实际调用，全部完成**。服务商报告计费字符 382，usage 从 4859 增至 5241 / 1000000，差额一致；冻结的保守上限为 2112 字符（含 XML）。没有重试、429、模型切换或付费升级。累计历史成功调用 242 次，另保留最早的 1 次 429 失败记录。

这是工程代理对合成结果的开发复核，不是独立人工盲测，不证明任意页面语义正确。所有通用候选仍为 `semanticVerified=false`。正式翻译、实际采集/OCR与隐私过滤、后端密钥管理和手机端验收仍未完成。

## 实现契约

- `translation_protected_facts.py` 不依赖语料 ID、预置答案、网络或凭据。
- 金额匹配使用原文位置，保留大小写、空格、小数分隔符及货币符号。仅支持已有明确货币语法；已检测但不能完整绑定的币种、带符号金额、歧义精度/千位写法拒绝处理。未识别的其他金额语法不在本轮支持保证内。
- 使用 DeepL `tag_handling=xml`、`tag_handling_version=v2`、`ignore_tags=["keep"]`。原文每个金额用唯一标签包裹，整页原始可见文字仍作为完整 context，评分准则和答案不进入请求。此用法依据 [DeepL XML 文档](https://developers.deepl.com/docs/translate/translating-xml) 与 [请求参数](https://developers.deepl.com/api-reference/translate/request-translation)。
- 返回仅接受限定的单根、平面 XML。金额文本、标签 ID、数量、顺序必须与本地原文一致；丢失、重复、嵌套、换序、额外属性、DTD/实体声明/处理指令或超长响应均保留原文。输出为普通文字，不把服务商标记交给 WebView。
- 去除包装后继续执行已有关键事实检查。即便原金额保住了，服务商额外补“美元”或把“每月”写成“每年”也会被保留原文。
- 法语 `37,80 €` 在展示中仍为 `37,80 €`；只在已验证金额片段的数值核对副本中将逗号改成小数点，不改显示原文，也不放宽旧校验模块。
- 本地日期只支持完整 EN/FR 正向有效性标签：`Valid on`、`Only valid on`、`Valid only on`、`Valid until`、`Valable le`、`Valable jusqu’au`，以及截止日明确写出的 inclusive/inclus。英文/法文月份分别匹配，验证真实公历日期、闰年和法语 1er。
- “某日有效”和“有效至某日”分开处理；原文没说 only 不添加“仅限”，没说 inclusive 不添加“含当日”。带额外条件、多个日期、否定、数字歧义、非法日期或不支持语法的有效性标签不截取部分转换。
- 本地日期来源、云译文来源、复用旧响应的证据分别记录；原始块 ID、位置、组由本地绑定，服务商不能重新分配。
