## 失配根因与验证

固定 RapidOCR 3.9.2 的 `main.py` 第175～191行在最终输出阶段以 `v.strip()` 删除空识别行，并同时过滤框。Latin 对中文返回空串时，最终列表与中文模型不再按行对应。不是两模型的检测框本身必然不同。

新脚本每张图只检测/裁剪一次，将同一裁剪交给两模型，并在过滤前保存原始文本及框身份。98组图片/倍率，98次检测、188次识别（4空输入不推理）、180个共同框，保留27个Latin空候选。按原上游最终输出规则重新过滤后，196份文字、位置和分数全部与历史报告精确一致，证明未通过改输入或改输出美化结果。

复用e123c55冻结字形规则，原17图在1/2倍都13/17准确；历史新增30图在两倍设置均23/30准确，修复了大量因丢框造成的不可用。然而两模型都正确读出独立时间块“18:00.”时，旧规则因没有汉字或Latin字母仍返回待核对；原本准确的法语页变为不可用。该版选择规则仍不接入Android。

证据：[完整共同框报告](evidence/shared-box-candidates/2026-09-24/shared-box-report.json)。原文、空候选、裁剪哈希、框、模型、上游源码及输入指纹均保存；不将同字体旧语料的计数宣称为一般准确率。

## 阶段二：预先锁定候选v2

在上述结果之后提出v2，后续结果属于新规则评估，不回写v1成功：

1. 同一页面及框ID、几何、阅读位置完全匹配才可关联，空模型结果仍占据原框。
2. 两候选逐字符相同且非空，则原样保留，来源标为双模型一致；这不是语义置信度保证。
3. 否则中文候选有汉字则保留中文候选；否则Latin候选有Latin字母则保留Latin候选。
4. 其他情况保留两候选并标待核对；不猜数字、不取最大分数、不改写原文。

先对同一98组/180框评分，报告包括准确页减少和待核对在内的所有退步。只有这些已有语料整体改善且相对中文模型无退步，才进入独立Android选择/身份验证实验；正式三语质量仍需新的冻结语料、多字体和关键字段检查。现阶段不扩展正式放大镜授权。
