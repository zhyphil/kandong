# 清晰增强内存与生命周期迭代 · 2026-09-24

用户离开期间授权继续执行任务清单，本轮范围是已接入的清晰增强、自动生命周期验证和大字号菜单结构检查。唯一根目录保持KanDong，没有操作或更新用户真机。

## 修复依据

此前华为15分钟混合使用PSS为60.8→80.3MiB、峰值84.3MiB，但选区和倍率有变化；不足以判断泄漏或归因。只读源码审计确认两类可独立处理的问题：

1. 输入请求虽然只保留一执行、一待处理，已完成的每张图却各自排入主线程回调。慢消费者测试可累积100个回调及其像素；暂停/关闭也要等到回调执行才回收这些结果。生产采集本身也在主线程，因此这不证明用户那次使用曾发生无限积压。
2. 每次新选区帧创建direct上传缓冲区，每次镜面输出创建ARGB整数数组；1096×379镜面每帧数组约1.58MiB。这是已定位的分配压力，不是已证明的泄漏链。

在改实现前，临时接入既有JUnit的5项行为测试有4项失败；修复后交付10项及原队列5项均通过，见[回归证据](evidence/memory/2026-09-24/regression.json)。

## 最终行为

- `LatestRenderWorker`分别限制待处理请求与待交付结果；只有一个最新完成槽和一个交付回调。被替换/失效的未交付结果立即回收，排队回调不持有逐帧像素。旧代结果不能覆盖新选区。
- 暂停、关闭清空待交付结果，后台渲染返回后丢弃迟到帧；GPU仍在拥有它的线程关闭。终止后重复失效不再向已关闭的线程池调度。
- 失败通知优先，等待通知时暂停该代渲染；不会被后续成功画面吞掉。交付被拒绝时清空结果并关闭资源，不向同一失效的接收端反复投递。
- 新的同步`renderViewportRgba`复用上传、读回和ARGB数组，先验证尺寸/字节数/设备上限，每次复制当前数据；缩小只读取有效区域。容量按有上限的倍增扩容，到暂停/关闭时释放引用。
- 上传上限400万字节、读回800万字节、ARGB200万个整数；这些是单项scratch上限，不是整个应用内存承诺。已有GL纹理、Bitmap、系统共享缓冲区另占内存。
- 公共`Input.fromRgba/pack`仍提供独立不可变快照。每张输出仍是独立Bitmap，没有把正在显示的Bitmap重新拿去覆写；合成测试验证下一帧不改变上一张图。创建语义参考[Android Bitmap API](https://developer.android.com/reference/android/graphics/Bitmap)。

字体、密度、底层App布局、取景框、手势和镜面算法都未改；没有新增权限、文字读取、网络或画面保存。

## 固定条件观察

修改前在专用API36合成页运行3分钟并收起1分钟：13个运行样本、13个收起样本，收起时采集/GPU/Bitmap全部停止或清空，计数保持不变。候选版完成600.01秒固定2倍、508×154选区/1017×309镜面观察：41个样本始终展开，增强持续推进，渲染和清理错误均为0。PSS起点59.7MiB、终点65.1MiB、峰值66.0MiB，前/后10样本中位数64.4/64.8MiB；只能描述本次采样，不能证明没有泄漏或长期有界。

随后收起60秒、每5秒采样，共13样本：处理计数不再增加，采集停止、surface分离、GPU关闭、两类Bitmap清空，PSS约55.8～56.0MiB。最后恢复并主动关闭，验证共享/服务/自有悬浮窗均移除，再关闭专用模拟器。[数值分析](evidence/memory/2026-09-24/analysis.json)、[运行原始记录](evidence/memory/2026-09-24/optimized-active.json)、[收起原始记录](evidence/memory/2026-09-24/optimized-paused.json)、[最终清理](evidence/memory/2026-09-24/final-stop.json)。

两轮预热、页面操作历史、进程状态和时长不同，不能用它们计算真实手机节省多少内存；模拟器温度、电量和供电数字不用于热量或耗电结论。

此前的[华为15分钟记录](SUSTAINED_VALIDATION.md)保持原样。候选版还未安装华为；目标机长期PSS趋势、重复生命周期、主观流畅度与实际断电耗电仍需补验。

## 复用生命周期检查

仅使用本项目专用AVD `KanDong_Phase0_API36`。先安装本地debug的compat与fixture，在模拟器手动启动看懂、允许屏幕共享并开启增强，然后启动合成测试页：

~~~sh
adb -s emulator-5580 shell am start -n com.kandong.fixture/.FixtureActivity
python3 scripts/compat-lifecycle-check.py --serial emulator-5580 --cycles 20 --out /private/tmp/kandong-lifecycle-new.json
~~~

脚本在任何ADB调用前拒绝真机标识，再检查AVD名称和模拟器属性；触摸前要求自有合成页在前台。只记录自身数值，不保存截图。检查完主动关闭本次模拟器放大镜；失败时也只停止该专用模拟器的看懂服务。它不负责安装、授权或打开真实App。
