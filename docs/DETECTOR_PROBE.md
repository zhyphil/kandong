## 固定数据与规则

[导出器](../scripts/export-detector-probe-fixtures.py)使用既有固定Python环境，只读取项目自编trilingual-v1图及生成的颜色校准。10组包括EN、FR、简体、繁体、混排、空白、彩色控制，以及输入宽959/1499/2001的三个控制图。后者输出宽960/1504/1984；不使用文字答案调整算法。

[清单](../modelprobe/src/androidTest/assets/detector-v1/manifest.json)SHA256 74aa1e39c8d3187ee2388ad07bb228e3c876c0486ccd02c47208942d26f2c80a，共62文件。各组保存源PNG、上游实际缩放PNG/ARGB、输入float32、原始输出float32及二值图，全部压缩文件另记解压后长度/哈希；使用.f32z/.u8z/.argbz避开AAPT对.gz的改写。

检测预处理与识别预处理分开：
- 最长边按实际版本选择960/1500/2000；比例取整后32倍数偶数舍入，零尺寸拒绝。不是配置1280硬上限，详见[规则核验](DETECTOR_CONTRACT.md)。
- 已缩放不透明ARGB转BGR的NCHW布局。先float32像素乘float32(1/255)，再转double减0.5、除0.5，最后float32。不能替换成此前识别器的除255计算；全256个灰度值中111个数值位会改变。
- 输入维度最大4096，结果维度最大2048且总像素不超过1,048,576；这是当前实验预算，不能推断整屏处理预算已达标。
- 本轮模型接收上游已经缩放的固定像素，验证Kotlin打包和推理；原始整图在Android上的缩放影响仍是后续门槛。

采用[固定上游实现](https://github.com/RapidAI/RapidOCR/blob/v3.9.2/python/rapidocr/ch_ppocr_det/utils.py)实际数据作参考，未复制整套框架。资源处理参考[ORT Java Tensor API](https://onnxruntime.ai/docs/api/java/ai/onnxruntime/OnnxTensor.html)；关闭张量不等于立即回收应用持有的直接缓冲区。

## 预先固定的数值门槛

设备运行前冻结：打包输入逐位一致；模型输出为FLOAT [1,1,H,W]，必须有限且位于[0,1]。每值绝对误差不超过1e-5 + 1e-4 * abs(reference)，平均绝对误差不超过1e-6。二值图按严格value > float32(0.3)，要求零翻转；保留逐组输出哈希、位差数、误差及接近阈值的统计。容差是本轮数值验证规则，不是OCR准确率标准；失败时不能根据观测结果放宽。

模型使用CPU、顺序执行、1个内部/外部线程、ALL优化、关闭CPU arena和后续遥测。宿主SDK导入发生在仓库外指定目录，导入后关闭遥测；曾出现初始化设备ID持久化警告，不据此宣称已完成宿主网络审计。
