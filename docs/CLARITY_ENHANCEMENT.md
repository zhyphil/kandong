# 清晰增强：兼容版试用功能

用户已在独立实验中选择 C「轻度锐化」，并确认 GPU C 同样清楚、好读。0.1.1-clarity-dev/code7 在实际兼容放大镜中加入可关闭的本机增强；v0.1.0 已发布资产保持原样。

## 使用

打开首页或悬浮窗菜单，开启「清晰增强」，关闭菜单后继续使用。首次安装默认关闭，之后记住用户选择。新共享会话仍默认2倍。直接拖红框、右上角自由调宽高、镜面单指平移/双指1～5倍、滑杆同步与自动换位沿用核心基线。

这是有限的笔画边缘改善，不补造文字或恢复原图没有的细节；只有本机计算，不调用外部服务。若觉得卡顿、过锐或手机变热可关闭。设备不支持或渲染失败时提示并自动关闭此选项，回到普通画面。

## 实现边界

- graphics 共享 GLES3/EGL 后端；qualitylab 仍是独立无权限的合成验证应用，生产代码不依赖实验页面/文件导出/CPU参考。
- 只使用既有本次授权的选区 RGBA。画面不保存、不上传、不打印；不新增权限。已有显示窗口 FLAG_SECURE 保留。
- 输出始终等于镜面物理像素尺寸。CPU仅生成每轴采样系数；轻度锐化与插值在GPU执行，随后读回本地Bitmap显示。不是全选区乘5生成巨大图片，也不是GPU直接呈现方案。
- MagnifierViewport仍是倍率、平移的唯一来源。增强输出使用单位显示矩阵，不再重复缩放。手势变化时立即显示普通变换画面，异步结果到达后替换；旧视窗结果不能覆盖新位置。
- 工作线程最多1个执行中请求和1个可替换待处理请求。输入为独立选区字节，不跨线程使用UI会回收的Bitmap。实际显示结果通过独立主线程Handler回传，服务取消自身回调不会遗失待回收Bitmap。
- 选区/变换变化失效旧结果；收起/菜单清空字节和Bitmap、关闭采集surface并请求工作线程释放GPU纹理/上下文；执行中的驱动调用不可强行中断，返回后丢弃结果并释放。结束/锁屏/旋转/撤销采用相同失效与资源释放规则。
- 输入上限100万、输出200万像素，并核对设备纹理/视窗上限；超限自动回到普通画面。1倍不锐化，整数位置像素直通，分数位置双线性；大于1倍使用已验证的轻度锐化+Mitchell采样。选区外为白色。

## 验证状态

当前相关构建成功：compat debug/release，qualitylab debug。compat53、graphics12、qualitylab20项JVM测试通过；Lint分别0错误/8警告、0/0、0/12。新增用例保护待处理替换、迟到结果、暂停释放、关闭与失败回退，以及输入所有权、连续倍率/分数平移/边界和内存上限。未声称本轮新测试完成了先红后绿循环。

专用API36已通过144组GPU视窗对照，覆盖9种倍率、4组位移、普通/1×N/N×1/单像素输入，使用独立Double参考与原误差门槛。华为同样通过144组，两者与独立Double参考的最差通道均差0.0646、单通道最大误差1（固定门槛均差≤0.1、最大≤2）。两设备原48组整数对照复跑通过。

API36九组实际交互通过，包括开启/关闭、拖框/调大小、双指/滑杆/平移、收起/菜单暂停恢复、停止、下一会话默认2倍与锁屏。另通过旋转停止、连续5次GPU释放/重建与最终包开关回退抽查。只读独立审查发现超大视窗异常影响普通画面的P2，已修复并加入3项回归；报告版本硬编码P3改为读取构建版本。华为早期数值报告的旧标签保留并标注实际安装包，不篡改原结果。

华为1096×384固定视窗合成短测（2轮预热/10轮样本，包含渲染读回与Bitmap，未含采屏/UI）中位数：505×209选区2倍31.08ms、5倍29.46ms；1096×384选区2倍33.77ms、5倍32.60ms。所有组P95≤35.57ms，不能称为端到端帧率。最终code7已安装华为，用户手动开启增强并授权共享；读取自身状态确认已输出188帧增强画面，实际镜面1096×379、3.35倍与滑杆235同步，回退及清理错误均为0。用户随后对拖框、双指缩放、收起恢复反馈“文字清楚，操作顺畅”，通过目标机短时主观验收；没有截取手机屏幕。详见 [验证记录](evidence/clarity/verification.json)。

## 未完成的性能范围

合成短测不代表实际采集到显示的端到端延迟、持续发热/耗电、所有App/OEM或长辈长时间识读。下一步在目标手机分别试浏览器与日常App，切换增强对照、拖动/捏合/收起恢复，并进行持续使用测量。默认不启用增强；不发布新Release直到相应体验确认。
