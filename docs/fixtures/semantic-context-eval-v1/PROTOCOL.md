# 新整页候选布局的边界评估

基点1199609。冻结24页独立单语输入：英语、法语、简体、繁体分别成页，共93个手工候选。它们是开发者了解当前规则后设计、在首次执行前固定的反例集；不是外部盲测、真实OCR、模型质量或翻译质量样本。

本轮只运行现有空间关联、分组与按需请求契约，不修改规则，不调用OCR模型、供应商或读取真实屏幕。宽1200、高2400用于四段结构契约；每个输入有原文、四角、分段和独立标签。strip/分数/模型标识均为构造值，不冒称实际推理收据。

预期完整关系由源句含义及编写布局预先标注，不由算法生成；包含普通两行、不同列、重复观察/冲突/裁剪、同词不同位置、较宽间隔/缩进、前置条件和后置例外。带例外/仅限/否定/前提的段落不能仅把其中两行当成完整退款结论；可以保留原文。相邻的无关客服/配送文字不强行纳入条件。

分别统计：
- 错误放行：请求涉及受保护条件文字，但来源成员集合不是一个标注的完整组（无论两行组或孤立片段）。
- 保守遗漏：一个完整预期组没有成为请求目标，且其中任何来源都没有被作为不完整目标发送。
- 正确完整目标、未涉及条件的普通目标、中文不请求翻译分别列出。
- 数据完整性独立要求全部候选/原文/四角/分数位保持，整页上下文未裁剪；不能靠去重删除提高分数。

新增JVM输入只由corpus的输入字段生成，不含oracle；运行真正的现有Kotlin组件并输出观察。宿主评分器将观察与冻结oracle比较。若发现错误放行，质量闸门返回非零并保留结果，不能把诊断工具或技术测试通过写成规则质量通过。

历史fr-seam四成员歧义另作来源拓扑分析：只列出现有同文/异文/位置/关联边和跨行关系，不引入赢家或生成新译文；也不把历史OCR标为本轮新推理。

本轮上限：24新手工页＋1历史页；零网络/设备调用，零依赖/运行算法调整。使用既有unittest/JUnit；相称本机回归后更新任务/交接并Conventional Commit、正常push。
