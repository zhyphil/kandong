# 独立 Android 模型探针

当前阶段：独立Android同张量技术验证通过，继续图片预处理/检测对齐。本实验是PaddleOCR候选的下一项技术验证，**不是完整Android OCR，也不是翻译功能**。

## 要证明什么

相同模型和相同float32输入，在Mac、华为LIO-AN00/API31及专用API36上的解码输出是否一致；明确取消、后台、旋转和资源释放能力。正式放大镜和既有文字实验均不改动，使用独立包com.kandong.modelprobe「看懂模型验证」。

10项输入来自5张自编图（英语、法语、简体、繁体、混排）的2倍版本，各送入Chinese和Latin两个识别器。Mac实际检测、裁剪和归一化后记录模型输入；不使用人工框或原文答案裁剪。批次按实际宽高比排序，**不等同于页面阅读顺序**。两个模型均处理全部图；参考文字只在推理之后比较。

输入manifest SHA256：126d8d3860d5a4ea098f0875838dbed51a55d8a321f50d409805d394a460061c。10项合计18行、压缩输入825104 bytes，单项最多796608原始字节；输出最多3198990个float。字典、模型、压缩/解压输入都单独取指纹。CTC保留原始字符，比较不做NFC或空白修正。

Latin识别中文时本来会输出残缺文字。如果手机重复了相同的残缺结果，它只能算“运行输出一致”，**不能算中文识别正确**。识别质量与[宿主候选记录](RAPIDOCR_SCREENING.md)分别验收。

## 模型与边界

- Chinese模型16,631,306 bytes、Latin模型7,904,513 bytes；固定RapidAI/ModelScope v3.9.2文件和SHA，权重不修改。两者只保存在本地忽略的assets/models，不进入Git；字典与自编张量随包。
- 模型发布卡明确声明Apache License 2.0，卡片、PaddleOCR/RapidOCR许可及来源指纹随实验包保留。上游MODEL_LICENSES链接404，尚未独立审计转换步骤；不声称由Paddle官方直接发布这些ONNX文件，也不因此扩大正式发布授权。
- 使用Microsoft官方ONNX Runtime Android1.30.0。实际AAR53,040,218 bytes、SHA256 e7fb945e402205f6db858d65bb78d2bdb0812317b383976c9e3bceb4862c73f1；AAR自带INTERNET、ACCESS_NETWORK_STATE和TelemetryInitializer。实验清单必须显式移除两项权限及初始化provider，并在模型创建前关闭运行时统计。最终以APK检查为准，不能只引用这份设计。
- CPU单线程、串行模型；不注册NNAPI/GPU，不强制打断native调用。取消立即撤销发布权，等在途完成后在同一工作线程关闭结果、张量和会话；清理完成前禁止重开。ORT环境的Java close为no-op，环境按进程寿命管理，不宣称每次销毁整个库。
- 不申请读屏/文件/相机/联网权限，不接受外部图片/Intent参数，不自动恢复。私有报告只含合成数据；模型加载和推理错误用固定错误码。

## 复现

在KanDong根目录显式执行 `python3 scripts/prepare-modelprobe-models.py` 下载并校验两个固定模型。该操作不是Gradle自动步骤；只构建正式放大镜不会因缺失实验模型失败。然后针对modelprobe构建和测试。

重新生成探针输入时，先用[scripts/screen-rapidocr-fixtures.py](../scripts/screen-rapidocr-fixtures.py)在临时目录生成固定18张图的原图/2倍处理图；再用[scripts/export-modelprobe-tensors.py](../scripts/export-modelprobe-tensors.py)，指定模型、已处理图片和临时输出目录。导出过程核对发布模型、输入像素与既有宿主结果，保留真正送入模型的batch顺序。生成结果应与固定manifest及全部资产指纹一致；不能静默更新基线。

## 打包回归

首次源码检查和构建通过后，实际APK核对发现Android打包工具将`.f32.gz`自动解压并去掉后缀，导致运行时预期文件不存在。改用保留GZIP内容的`.f32z`后缀；模型、压缩字节和原始张量均不变，manifest因文件名变化重新固定指纹。`assembleDebug`增加实际APK的文件集合与逐字节检查，防止仅源码通过而交付包不可用。旧问题包未安装。

## 实际验收 · 2026-09-24

- 最终17项JUnit、debug构建、Lint通过（0错误/4提示）；APK签名和16KiB对齐检查通过，合并APK无权限、无TelemetryInitializer，仅自有入口导出。ORT二进制仍包含统计相关代码，不能称其源码没有遥测。源码聚合SHA b2a2a714cc3b4a4e46c971f875cc2707cdfbe1e71d51d61a9158b201cee36b33，原正式/既有实验129个受保护文件不变。
- 最终通用debug APK 160,745,940 bytes（约153.3 MiB），SHA a1859b3b3cc9e6e176333af7ee28d4f0e28fa70f40b0c652488cff8084ce8157；两设备实际安装包SHA均相同。大包包含多ABI运行库，仅内部实验，未做正式体积优化/发布。
- 华为API31和专用API36各10项＋手动重开10项；输入、原文、完整argmax指纹跨设备/重开一致。两轮每轮24项原生资源创建/关闭计数相等，完成报告在关闭后保存。华为首轮3104ms，API36首轮1436ms；包含校验、加载与推理等，不是持续使用性能或耗电结论。
- 两设备取消0项时冻结报告；退后台分别在华为2项、API36 4项时取消，返回不重跑；API36旋转0项取消并恢复原设置。取消报告如实记录清理尚在途，后续报告不覆盖它，手动重开成功。native清理中快速重开的拒绝由单元测试覆盖，未声称设备精确命中该竞态；未测试手机锁屏。
- 初次模拟器取消检查因进度文字挤动按钮未命中；将按钮移到进度之前，最终APK重跑通过。未把第一次完整运行误标为取消成功。独立只读审查未发现P1/P2，审查不含Gradle/设备；打包与按钮修复由父任务核查，未宣称修复后另做独立复审。
- 缺少本实验模型时，compat任务图dry-run通过；本模块校验明确失败且不下载，随后恢复模型。该项不代表重跑正式APK构建。导出器重新生成13个资产与当前版本逐字节一致；宿主脚本把SDK初始化工作目录限定到指定临时输出处，改动后原72项文字/框/像素不变。曾观察到SDK生成51byte初始化文件，未把它保留在仓库，也未因此声称宿主完全无网络活动。
