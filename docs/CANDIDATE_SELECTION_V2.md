# 共同文字框候选 v2：独立 Android 实验

2026-09-24：实验验收通过；三语质量、真实屏幕与正式翻译仍未验收。

## 改动

`SharedCandidates` 仅在 testShared 中编译，正式应用没有引入此选择器。每个候选携带页面身份、框ID、阅读序号和四角位置；相同页面及框完整匹配才能关联。保留空候选，按框身份关联而非列表位置，最终按阅读顺序输出。重复、缺失、跨页或不同几何的候选被拒绝；目前实验上限8框/每段4096字符。

规则在c5d61a2预先锁定：非空原文逐字符一致则保留，来源记为AGREED；否则优先中文候选的汉字证据，再考虑Latin候选的Latin字母证据；其余保留原候选并标REVIEW。不同数字不猜测，相同时间/金额不再仅因没有字母而被拒绝。AGREED不等于正确，字形证据不等于语言判定。任何原文均不做拼写、简繁或标点修正。

Java17对部分CJK使用块名＋码点生成字符名称，与Android的Unicode名称不同。测试发现这一差异后同时支持两种名称形式，并覆盖基础、扩展A/B及兼容汉字；未声称所有Unicode版本完全等价。

## 复现

已建立的专用模拟器启动方式见[模拟器文档](OCR_EMULATOR.md)。安装当前构建的主/测试APK后：

```sh
python3 -B scripts/run-candidate-emulator.py --output /private/tmp/kandong-candidate-new-run
```

入口固定专用AVD/端口，并检查本次APK指纹；输出目录必须新建。它会先跑本轮OCR，再传入本轮报告标识进行候选验证。旧`run-ocr-emulator.py`仍固定上一次基线，故不会静默接受新的测试包；当前测试应使用上述入口。验收目录另保留此次实际执行的临时入口原文；持久入口仅将根目录与身份JSON定位改为仓库路径。
