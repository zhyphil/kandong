# KanDong 产品定义

KanDong 是面向老年人，以及存在视觉、语言或数字使用困难人群的**智能屏幕放大镜**。核心是“不改变原 App 页面布局的跨 App 局部屏幕放大镜 + 利用整屏上下文的放大区域翻译”。

产品顺序：**看清 → 看懂 → 理解 → 会操作**。不是以通用 AI Screen Agent 为核心。

## 用户首先遇到的问题

“字太小，看不清；调大系统字体以后排版变了，按钮反而找不到。”
用户像拿一个放大镜那样，局部查看原屏幕。KanDong 不调整系统字体、不更改显示密度、不重排底层页面，也不重新绘制底层 App。放大镜里显示原内容的放大视图，原 App 的布局仍在原处。视觉上的放大坐标和 App 内部布局坐标要区别对待。

其次是“看清了，但这是法语/英语，我看不懂”。放大区域的原文与中文可以就地切换，不需要复制、离开 App、粘贴、再返回。

## 首批文字识别语言

首版分别支持**单一英语、单一法语或单一中文页面**。按用户最新修正，同屏或同块混排不在当前语言测试及验收范围，不再阻塞翻译推进。中文是可识别的源文字，不能只因界面或译文是中文就算支持；简体和繁体分别记录实际覆盖。

识别与翻译分开：保留当前单语页的完整可见原文、位置与语义关系；点击“翻译”后，结合整屏上下文将英法内容译为中文，再按选区展示；中文保留原文。单语页可用整页证据确定源语言，不要求每个短按钮独立识别语言；证据不足仍提示不确定。验收重点是译文准确、上下文利用和对应显示，见[当前计划](SINGLE_LANGUAGE_TRANSLATION.md)。正式文字识别/翻译尚未接入。

## 产品层级与优先级

| 优先级 | 用户入口 | 用户得到什么 | 当前阶段 |
| --- | --- | --- | --- |
| P0 | 🔍 原文放大 | 跨 App 局部取景，自由调整宽高、独立1～5倍滑杆（默认2倍）；显示窗自动避到另一侧，快速关闭 | Phase 0A，当前 |
| P0/P1 | 翻译 | 利用当前页面整屏上下文理解法语/英语，在放大区域按元素显示大字中文，保留原文可核对 | Phase 0B，下一项 |
| P1 | 帮我看懂 | 对当前内容用短句、少术语解释，突出金额、时间、日期、限制 | Phase 1 |
| P2 | 下一步怎么办 | 有依据地解释下一步，原 App 上框出目标，用户亲自点击 | Phase 2 |
| 后续增强 | 读给我听 | TTS、高对比度、长辈操作优化、性能/电池优化 | Phase 3 |

安全、隐私和随时停止是各阶段的基础，不延后到 Phase 3。

例：放大镜看见 `Correspondance à Bordeaux / 12 minutes`，中文应表达“在波尔多换乘 / 12分钟”。译文须忠实于原文；不能把“12分钟”自行解释成保证充足的换乘时间。
对于 `Non échangeable et non remboursable`，先译“不可改签，不可退款”；只有用户点“帮我看懂”时，再解释行程改变会带来什么限制。

## 翻译：点击启动，整屏理解，区域显示

默认打开和恢复放大镜仅展示原画面。用户想看译文时，点击镜面工具栏的“翻译”；系统处理当前屏幕的可见信息，把与红框对应的译文显示在放大镜展示区域。按钮须保留至少48dp可点范围，并显示处理/失败/待刷新状态；翻译尚未就绪前不提供冒充可用的正式入口。

按2026-09-24用户修正，翻译先获取当前前台页面整屏可见信息，保留标题、段落、卡片、按钮、单位和限制条件之间的关系，再决定放大区域里各元素的译文。红框决定显示哪些元素，不限制理解范围；不先裁成孤立小图再猜含义。整屏不包括滚动后才出现的内容或其他隐藏页面；缺失信息不能补造。

例如同屏有两张酒店房价卡片，红框圈住其中一个价格，而“每晚”“含税”和“免费取消截止日期”在框外。系统要依据同一张卡片的完整可见信息翻译，并保持价格、单位、条件的归属，不能把另一张卡片的退款条件套过来。若选区切断一句话，要保留可见的完整语义组；镜面可用紧邻的中文卡片承载较长译文，不为了塞进原框而裁掉否定或限制，也不改动原App。

同一页面内移动红框可复用仍有效的上下文；原页面滚动、切换、内容改变或结果过期时撤下旧译文，等待用户再次点击“翻译”，不自动处理新页面。原文、译文可核对；不能可靠对应时说明未识别，保留原文。全屏文字识别和模型利用上下文的能力都需要独立验证，已有合成OCR结果不代表该功能完成。详细契约见[翻译上下文设计](TRANSLATION_CONTEXT.md)。

## 界面原则

首页围绕“看不清时，打开放大镜”。浮动入口为放大镜图标；镜面工具栏提供“翻译”按钮（可配翻译图标和短标签），点击后才处理当前页面；默认只显示原文放大，解释、引导、朗读属于二级入口。尚未实现的功能不能伪装成可用按钮。OCR、LLM、Accessibility Tree 等只出现在工程文档中。

当前华为兼容版采用分开的两个控制：直接拖动红框移动选区，右上角小角柄自由调整宽度、高度；镜面内双指或倍率滑杆连续选择1～5倍，每次新会话默认2倍。调整红框不改变倍率，调整倍率也不移动或改变所选区域。字形保持原比例。若放大后的内容超出固定显示窗，用户在放大画面内滑动查看其余部分；内容较小时按所选倍率居中，允许留白。源区偏上时显示在下方，偏下时显示在上方；中间设小范围缓冲，避免来回跳。双指缩放时数字和滑杆同步，单指仍用于镜面平移。操作原App前先收起；红框中的触摸用于移动选区。

取景区域和放大显示区域可以分开，但操作必须容易理解。原生系统窗口模块仍保留为平台验证路线，其2/3/4控制条不能代表新交互已实现。老人能否理解分区镜面仍需实际验证；不能用技术成功代替可用性成功。

## 随用随开的辅助层

放大窗可收起成可拖动、贴边的放大镜悬浮按钮，再点一下恢复原选区与倍率；收起时暂停画面处理，保留系统共享。菜单承载使用帮助、隐私及后续翻译设置/账户/订阅的位置，未实现条目明确标注准备中。图标缩小视觉占位，点击区域仍适合长辈操作。交互细则见[UX](UX.md)。

## 边界与验证

Explain → Highlight → Human taps 只属于后续引导层，不能反过来决定核心产品。所有最终操作仍由人完成；不自动点击、输入、确认、提交、购买、支付。
目标是跨 App 使用，但不承诺任意系统、任意 App、锁屏、安全窗口或厂商都支持。Phase 0A 的第一个 Go/No-Go 必须有真实 Android 手机上的局部放大、拖动、倍率和底层布局证据。市场需求和长辈理解程度还需独立验证。
