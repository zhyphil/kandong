# 产品方向

## 真实问题

长辈看不清手机小字；系统整体放大后原 App 排版可能变化，按钮更难找；外语购票页面又增加理解负担。KanDong 在现有页面上提供临时帮助，用户不必换一套桌面或改变原布局。

## 不变的交互原则

**Explain → Highlight → Human taps**：先解释看到的内容，再指出有证据的控件位置，最后由用户判断和操作。不能把识别到一个按钮解释成已理解其后果。未知时明确说无法确认。

## 阶段边界

Phase0 面向开发验收人员：读取 → 候选原标签说明 → 框选。它证明 Android 技术链路，不声称会翻译、理解行程、判断费用或推荐购买。
Phase1 面向真实使用场景：“帮我看看/看懂” → 大字中文概述与关键项 → 用户选择需要解释的内容 → 有依据时指向原控件。
后续才考虑按需 OCR、翻译、TTS 和局部放大；每项都需要独立权限/隐私与设备验证。

## MVP 不做

自动点击、自动输入、自动购买；远程控制；账户/社区；老人桌面；后台持续采集；默认云端上传；同时开发 iOS 或 HarmonyOS NEXT。

## 未来用户验证

先观察长辈能否独立叫出帮助、读懂一句说明、找到原按钮、停止辅助。记录任务成功与失败原因，区分“字看清了”和“后果理解了”。Phase0 技术验收不能代替这些观察，也不能据此声称需求或市场已经验证。
